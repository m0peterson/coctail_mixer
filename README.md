# Коктейльный миксер

Веб-приложение для домашнего бара: отмечаешь, что есть дома, и видишь, какие коктейли можно смешать прямо сейчас, чего не хватает до остальных и что выгоднее всего докупить.

- **Мой бар** — 101 ингредиент по категориям, пресеты («Домашний бар», «Вечеринка», «Тики»), поиск, ссылка «поделиться баром».
- **Что смешать** — готовые коктейли, «не хватает одного», «не хватает двух». Учитываются замены (золотой ром вместо белого, водка вместо кашасы) и домашние заготовки (сахарный сироп из сахара, гренадин из гранатового сока).
- **Что докупить** — какая бутылка откроет больше всего новых коктейлей, плюс список покупок на 3 позиции.
- **Рецепты** — 94 коктейля: классика IBA, современные хиты и пара безалкогольных. Пошаговые инструкции, пересчёт на N порций, объяснение техник, похожие коктейли.
- **Тиры** — тир-листы S–D по лёгкости приготовления, по «круто и необычно» и по их комбинации (ползунок решает, что важнее), плюс карта «легко и круто / сложно, но того стоит».
- **Крепость и питкость** — оценка градуса готового напитка с учётом таяния льда, пересчёт в «стопки водки», метка «коварный» для тех, что пьются как сок, а бьют как водка.
- **Подбор** — 8 вопросов о вкусе, настроении и том, что точно не надо; выдача с процентом совпадения и причинами.

Работает офлайн после первого открытия (PWA), ставится на домашний экран телефона. Бар и ответы хранятся в браузере, сервер и аккаунты не нужны.

## Запуск локально

Нужен Node.js 20.11+. Зависимостей нет.

```bash
npm start        # http://localhost:8080
npm test         # тесты данных и логики
```

Без Node подойдёт любой статический сервер: `python3 -m http.server -d public 8080`. Открыть `index.html` напрямую из файла не получится: браузеры не грузят ES-модули по `file://`.

## Деплой

Сборки нет: публикуется папка `public` как есть. Всё ниже бесплатно.

### Netlify

Самый быстрый вариант без Git: открой [app.netlify.com/drop](https://app.netlify.com/drop) и перетащи туда папку `public`. Через минуту будет ссылка.

Через Git: **Add new site → Import an existing project**, выбери репозиторий. Настройки подтянутся из `netlify.toml` (publish: `public`, без команды сборки). Кнопка для публичного репозитория:

[![Deploy to Netlify](https://www.netlify.com/img/deploy/button.svg)](https://app.netlify.com/start/deploy?repository=https://github.com/m0peterson/coctail_mixer)

### Vercel

**Add New → Project**, выбери репозиторий, ничего не меняй: `vercel.json` укажет папку `public`. Или из терминала: `npx vercel --prod`.

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fm0peterson%2Fcoctail_mixer)

### Cloudflare Pages

**Workers & Pages → Create → Pages → Connect to Git**. Build command оставь пустым, Build output directory: `public` (или подхватится из `wrangler.toml`). Без Git: `npx wrangler pages deploy public`.

### GitHub Pages

1. **Settings → Pages → Source: GitHub Actions**.
2. **Actions → Deploy to GitHub Pages → Run workflow**.

Чтобы публиковать на каждый пуш в `main`, раскомментируй блок `push` в `.github/workflows/pages.yml`. Все пути относительные, поэтому сайт работает и по адресу вида `user.github.io/coctail_mixer/`.

### Render

**New → Blueprint**, выбери репозиторий: `render.yaml` создаст статический сайт из `public`.

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/m0peterson/coctail_mixer)

### Surge

```bash
npx surge public
```

## Как устроено

```
public/                 ← это и есть сайт
  index.html
  css/app.css
  js/
    data/ingredients.js ← каталог ингредиентов: крепость, редкость, замены, домашние заготовки
    data/cocktails.js   ← рецепты
    core/               ← чистая логика без DOM (её проверяют тесты)
      metrics.js        ← крепость, лёгкость, тиры
      matching.js       ← что можно сделать, что докупить
      quiz.js           ← вопросы и подсчёт совпадения
    ui/                 ← отрисовка экранов
    main.js             ← роутинг (#/bar, #/mix, #/tiers, #/quiz, #/all, ?c=рецепт)
  sw.js                 ← офлайн-кэш
tests/                  ← node:test, без зависимостей
```

Роутинг на `#`, поэтому хостингу не нужны правила перенаправления, а ссылка на конкретный рецепт (`#/all?c=negroni`) открывается сразу.

### Как считаются оценки

- **Крепость.** Сумма спирта по ингредиентам делится на объём с учётом воды от льда. Для стира используется формула из «Liquid Intelligence» Дэйва Арнольда, для шейка линейное приближение к его замерам. Что выходит: сухой мартини ≈26%, Манхэттен ≈26% (у Арнольда в замере ≈27%), Негрони ≈19%, Дайкири ≈16%, джин-тоник ≈9%. Считай это оценкой с погрешностью ±2–3%, а не лабораторным замером.
- **Лёгкость.** 5 минус «очки возни»: метод (шейк и стир по 1, слои 2), доп. техники (белок +0,8, долгий шейк +1,5, колотый лёд +0,3…), домашние сиропы и по +0,4 за каждый ингредиент сверх двух.
- **Круто и необычно** и **питкость** — экспертные оценки от 1 до 5 в данных рецепта. Это субъективно, правь под себя.

### Добавить коктейль

Добавь объект в `public/js/data/cocktails.js` по образцу соседних (формат описан в шапке файла) и запусти `npm test`: тест проверит, что все ингредиенты существуют, единицы и теги корректны, а крепость правдоподобна. Новый JS-файл нужно также вписать в `PRECACHE` в `public/sw.js` (тест напомнит).
